git push rejected: non-fast-forward

Someone else's commit reached main before yours, and your commit doesn't have theirs in its history. Git won't move a branch backwards, so the remote refuses. Here is the line, what Git checked, and the pull that fixes it.

$ git push To ../origin.git ! [rejected] main -> main (non-fast-forward) error: failed to push some refs to '../origin.git' hint: Updates were rejected because the tip of your current branch is behind hint: its remote counterpart. If you want to integrate the remote changes, hint: use 'git pull' before pushing again. hint: See the 'Note about fast-forwards' in 'git push --help' for details.

What Git checked

A push asks the remote to move its main from the tip it has to the commit you're sending. Git moves a branch forward only: the commit you send must have the remote's tip among its ancestors, so that nothing already on main falls off it. A move like that is a fast-forward.

Part 2 · Every element, in every state

Each element is reviewed against MASTER.md §7: 4.5:1 text and 3:1 edges in both themes, a 44 px target, a visible focus ring, pressed feedback within 120 ms without moving the layout, a disabled state that doesn't rely on opacity, 12 px minimum text, and no clipped or rotated labels.

03Button

primary: default · hover · focus · pressed
secondary: default · hover · focus · pressed
disabled · busy · quiet · small
  • Pills, 48 px high (44 px small), with 8 px between targets. Labels stay lowercase, like commands.
  • Hover changes the fill (4.5:1 kept). Pressed scales to 0.97 in 120 ms, which is a transform, so the layout doesn't move.
  • Disabled is dashed and muted, not faded, and keeps its label readable. Busy keeps its label, adds a spinner and aria-busy, and stops a second tap (replaces today's disable-every-button).
