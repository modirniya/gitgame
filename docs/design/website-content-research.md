# Website content: what to add, and the evidence

*Status: Current · Last verified: 2026-10-04*

What gitgame.online could add beyond the landing page ([ADR-0009](../adr/0009-a-landing-page-and-the-game-at-play.md)) and the game to get more impressions while staying on the subject of Git. Research done on 2026-10-04 across four angles: games and tutorials that teach Git by playing, what people search for about Git, what makes small browser games and developer projects spread, and how Git is taught in classrooms and teams. Every number links to its source as read that day; the Git release claims were checked against the cited release posts the same day, and nothing else has been re-verified since.

This document is the evidence, not the decision. What gets built from it goes into [phase-1-plan.md](phase-1-plan.md), and anything that changes a locked line of the [charter](../adr/0000-project-charter.md) gets an ADR. It uses the project's words ([conventions.md §5](../conventions.md)): the game has days and packs, not turns and rounds.

The highest-value content Git Game can add is a set of pages that explain Git's real terminal output line by line, because that niche is empty and it is the one Git demand signal still growing while generic "learn Git" traffic shrinks. Stack Overflow's "failed to push some refs" question has **3.9 million views**, "Updates were rejected because the tip of your current branch is behind" has 2.4 million, and Google autocomplete shows people typing these messages nearly verbatim, yet the only pages that exist are "how to fix" error catalogs; nothing explains Git's normal output such as `(forced update)`, `Already up to date.` or `Fast-forward`, which the game prints every day ([Stack Overflow](https://stackoverflow.com/questions/24114676/git-error-failed-to-push-some-refs-to-remote); [jvns.ca](https://jvns.ca/blog/2024/04/10/notes-on-git-error-messages/)). Meanwhile new [git] questions on Stack Overflow fell from **2,903 in 2024 to 319 in the trailing twelve months** and Wikipedia's Git article lost a third of its monthly views since 2024, so pages must target exact messages, exact flags and news hooks rather than "what is Git" ([Stack Exchange API](https://api.stackexchange.com/2.3/questions?tagged=git&site=stackoverflow); [Wikimedia pageviews](https://wikimedia.org/api/rest_v1/metrics/pageviews/per-article/en.wikipedia/all-access/user/Git/monthly/20240101/20261001)). Across every proxy, the Git formats that get shared for a decade are problem-first recovery guides and instantly usable visual sandboxes, not exercise collections: Oh Shit, Git has reached the Hacker News front page six times (peak **1,209 points**) while Git Katas, with 1,682 stars, never passed one point ([HN](https://news.ycombinator.com/item?id=15951825); [HN](https://news.ycombinator.com/item?id=39045512)). For growth, the one missing piece is a per-game result artifact (a public replay URL with an Open Graph image and a text share block) so a room link pasted into Slack previews as a result rather than the homepage; Wordle's text grid took it from 90 to 2 million weekly players in ten weeks ([Wikipedia](https://en.wikipedia.org/wiki/Wordle)). Educators are a live channel because GitHub Classroom was retired on 28 August 2026 after serving **3.73 million students and educators**, and engineering teams search for force-push, protected-branch and rebase-versus-merge policy, all of which map one-to-one onto the game's cards ([GitHub Community](https://github.com/orgs/community/discussions/205975)). The evidence argues against global leaderboards, calendar-day streaks, badges, generic cheat sheets and scheduled events. The months ahead offer Git 2.98 in December, Advent of Code season, Git 3.0 in spring 2027 and Git's birthday on 7 April.

## Searchers type Git's exact messages, and no site decodes them

Git's accumulated demand is overwhelmingly about undoing and syncing, which is also what the game's deck does. The three most-viewed [git] questions on Stack Overflow are "undo the most recent local commits" (**16.8 million views**), "delete a branch locally and remotely" (13.5 million) and "revert to a previous commit" (13.0 million); further down sit "force git pull to overwrite local files" (9.7 million), "resolve merge conflicts" (3.8 million), "properly force a Git push" (3.0 million), "fix a detached head" (2.9 million), "Undoing a git rebase" (2.4 million) and "Commit your changes or stash them before you can merge" (2.3 million) ([SO 927358](https://stackoverflow.com/questions/927358/how-do-i-undo-the-most-recent-local-commits-in-git); [SO 161813](https://stackoverflow.com/questions/161813/how-do-i-resolve-merge-conflicts-in-a-git-repository); [SO 5509543](https://stackoverflow.com/questions/5509543/how-do-i-properly-force-a-git-push); [SO 10228760](https://stackoverflow.com/questions/10228760/how-do-i-fix-a-git-detached-head); [SO 134882](https://stackoverflow.com/questions/134882/undoing-a-git-rebase)). Reflog demand hides inside those "undo" queries: the [git-reflog] tag holds only 96 questions, but the 2.4-million-view rebase-undo answer and the 2.0-million-view "move the most recent commits to a new branch" answer are both reflog recoveries ([SO 1628563](https://stackoverflow.com/questions/1628563/move-the-most-recent-commits-to-a-new-branch-with-git)). The lesson for page titles is to name the predicament ("undo a rebase", "someone force-pushed over my commit"), never the command.

Autocomplete shows that people search Git's wording nearly verbatim. Typing "git failed to push" completes to "git failed to push some refs to origin"; "git updates were rejected" completes to both "because the tip" and "because the remote contains work"; "git already up" completes to "git already up to date but not"; "git detached" completes to "git detached head fix" ([Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20failed%20to%20push); [Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20updates%20were%20rejected); [Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20already%20up)). The two "Updates were rejected" hints matter for accuracy: Git prints the same `! [rejected] main -> main (non-fast-forward)` line in both cases but a different `hint:` paragraph depending on whether the remote merely moved ahead or holds commits you have never fetched, and a decoder page must show both.

The supply side is thin and one-sided. DevErrors, GitScripts, Graphite and Komodor publish templated "how to fix" pages for error strings (DevErrors stamps each with "Last verified: December 6, 2025"), but none of them explains Git's success output ([deverrors.com](https://deverrors.com/errors/git-already-up-to-date); [graphite.com](https://graphite.com/guides/debugging-common-git-errors)). Julia Evans' "Notes on git's error messages" is the only widely shared page that treats the output text itself as the subject, and it covers nine messages ([jvns.ca](https://jvns.ca/blog/2024/04/10/notes-on-git-error-messages/)). The only systematic documentation of push summary lines, including the `+` flag and the `(forced update)` suffix, is the git-push man page ([git-scm.com](https://git-scm.com/docs/git-push)). That leaves `+ 8e1da02...b0ba026 main -> main (forced update)`, `Your branch is ahead of 'origin/main' by 1 commit.`, `CONFLICT (content): Merge conflict in <file>` and `Fast-forward` unexplained anywhere as a line-by-line decoder, and Git Game is the one site that already produces every one of them in context.

The pages that rank for Git concepts share a skeleton that static HTML reproduces easily, and they almost never show real output. Atlassian's "Merging vs. Rebasing" runs about **2,200 words with 8 code blocks (none showing output) and 10 SVG diagrams**; GitHub Docs' "About Git rebase" is about 1,100 words and shows the real interactive-rebase todo list; GitKraken wraps a FAQ in schema markup ([Atlassian](https://www.atlassian.com/git/tutorials/merging-vs-rebasing); [GitHub Docs](https://docs.github.com/en/get-started/using-git/about-git-rebase); [GitKraken](https://www.gitkraken.com/learn/git/git-rebase)). The two Git explainers that hit the HN front page in 2026, "Git Rebase for the Terrified" (266 points) and "The Git Commands I Run Before Reading Any Code" (2,338 points), are both about 1,200 words with 5 to 10 code blocks and no captured terminal output ([brethorsting.com](https://www.brethorsting.com/blog/2026/01/git-rebase-for-the-terrified/); [piechowski.io](https://piechowski.io/post/git-commands-before-reading-code/)). The recipe, then, is a one-paragraph definition, a concept section with a before/after commit graph (the game already draws these), exact commands, a "when it goes wrong" caution, a short FAQ and dense links to sibling pages, at about 1,200 words for one concept and 2,200 for a comparison. Pasting Git's real output verbatim with the Git version in the footer is the structural difference nobody else has.

That footer is not optional. Git ships a feature release every 10 to 12 weeks (2.48 in January 2025 through 2.56 on 28 September 2026), and 2.56 changed exactly the kind of text a decoder quotes: it added command-line slip detection (`git push origin/main` now suggests `git push origin main`) ([GitHub blog](https://github.blog/open-source/git/highlights-from-git-2-56/); [LWN](https://lwn.net/SubscriberLink/1094575/2385e98583715c2b/)). Both "Already up-to-date." and "Already up to date." circulate in indexed content, and the research could not pin the version where the spelling changed, which is itself a reason to state the version. Git 2.51 made `git switch` and `git restore` non-experimental "after 6 years", so the cards should decide which spelling they teach and the pages should say so ([GitHub blog](https://github.blog/open-source/git/highlights-from-git-2-51/)). Git 3.0, due in spring 2027, makes SHA-256 the default object hash and reftable the default ref store, which touches the abbreviated SHA-1 hashes the game shows in `tag`, `reflog` and `push --force` output ([GitLab](https://about.gitlab.com/blog/whats-new-in-git-2-56-0/); [LWN](https://lwn.net/SubscriberLink/1094575/2385e98583715c2b/)).

Beyond messages, the concept queries with sustained interest are rebase (autocomplete leads with "git rebase vs merge", then "onto", "interactive", "abort"), force ("git force push", "git force with lease", "git force pull"), and worktrees, which GitHub's own blog tied to AI coding agents in June 2026 and which autocomplete pairs with "claude code" ([Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20rebase%20); [Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20force%20); [GitHub blog](https://github.blog/ai-and-ml/github-copilot/what-are-git-worktrees-and-why-should-i-use-them/)). Rebase and force map onto the `rebase -X ours/theirs` and `push --force` cards; worktrees have no card, so a worktree page would be on Git but off the game. Bisect and blame are the inverse case: tiny Stack Overflow tag volume (126 and 131 questions) but recurring HN appeal for narrative "hunt the bug" posts, 232 points for "At the end you use `git bisect`" and 337 for Bayesian bisection in 2025 and 2026 ([HN](https://news.ycombinator.com/item?id=45791882); [HN](https://news.ycombinator.com/item?id=47557921)). Those fit the blame-the-hidden-bug mechanic as story pages, not reference pages.

## Recovery guides and visual sandboxes spread for a decade; exercise lists and quizzes do not

Two shapes of Git content get re-shared for years. The first is the blunt, problem-first recovery guide: ohshitgit.com is eight headings of the form "Oh shit, I..." followed by a command block and commentary, shows no real output, has 26 translations, and has reached the HN front page six times with 1,209, 713, 464, 412, 382 and 302 points, most recently in January 2025 ([ohshitgit.com](https://ohshitgit.com/); [HN](https://news.ycombinator.com/item?id=42728916)). The second is the instantly usable visual sandbox: Learn Git Branching has **34,112 stars**, five HN runs of 245 to 717 points between 2013 and 2024, and one third-party estimate of about 249,000 visits in December 2024 ([GitHub](https://github.com/pcottle/learnGitBranching); [HN](https://news.ycombinator.com/item?id=41546769)). Stars alone do not predict sharing: git-flight-rules has 42,592 stars but its best HN submission scored 4 points, Git Katas has 1,682 stars and 1,103 forks (classroom adoption) but never passed 1 point, and gitstery and Git-It peaked at 5 and 1 ([GitHub](https://github.com/k88hudson/git-flight-rules); [HN](https://news.ycombinator.com/item?id=15738674); [HN](https://news.ycombinator.com/item?id=39045512)). Launch posts with a story outperform lists of exercises: git-sim's "simulate before you run" post took 447 points, Oh My Git's 2024 thread with its 2.0-funding news took 412, and Devlands' "I struggled with Git, so I'm making a game" took 246 ([HN](https://news.ycombinator.com/item?id=34477976); [HN](https://news.ycombinator.com/item?id=39976634); [initialcommit.com](https://initialcommit.com/blog/im-making-a-git-game)).

Three traits recur in what spreads. One is a stable single URL that gets resubmitted every two to four years (Learn Git Branching five times, Oh Shit Git six, Git Koans three, the ndpsoftware visual cheat sheet four), which argues for making gitgame.online's landing page that re-shareable URL rather than spreading identity across subpages ([HN](https://news.ycombinator.com/item?id=5232415); [HN](https://news.ycombinator.com/item?id=2461700)). Another is humour that is honest about pain: Git Koans (305 points), "Git Commands Explained with Cats" (266) and git-blame-someone-else (230, 225 and 166 across three runs) all trade on it ([stevelosh.com](https://stevelosh.com/blog/2013/04/git-koans/); [girliemac.com](https://girliemac.com/blog/2017/12/26/git-purr/); [GitHub](https://github.com/jayphelps/git-blame-someone-else)). The third is problem framing over command framing, demonstrated by reflog: standalone reflog content barely registers on HN (the best is 14 points), yet reflog is the most-cited recovery in the 2025 Oh Shit Git thread alongside detached HEAD, interactive rebase deleting commits, force-push overwriting a remote and commits on the wrong branch ([HN](https://news.ycombinator.com/item?id=38620733); [HN](https://news.ycombinator.com/item?id=42728916)). Those five scenarios are, almost exactly, the game's day-by-day events.

The formats that do not spread are also clear. No Git quiz reached 150 HN points, and the query "git quiz" autocompletes to "git quizlet nclex", "radiopaedia git quiz" and "git quiz nursing", because GIT is also the gastrointestinal tract; "git glossary" picks up "gut vs git" ([Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20quiz)). Generic cheat sheets are saturated by the official git-scm.com sheet (17 sections, SVG diagrams, PDF), GitHub Education's PDF, Atlassian, GitLab, freeCodeCamp and GeeksforGeeks, and autocomplete for "git cheat" already names Atlassian and GitLab ([git-scm.com](https://git-scm.com/cheat-sheet); [Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20cheat)). The only differentiated cheat sheet would be one scoped to the deck's commands with real output, which is the decoder set under another name.

The competitive set of Git games has converged on a template that Git Game should not copy. The 2024 to 2026 entrants (GitMastery at 484 stars, Gitvana, Git Noir, GitSetGo, GitQuest, the Steam title "git gud", Devlands) all offer a browser or mobile terminal running real or simulated Git, no sign-up, XP, and differentiate by theme; GitMastery is adding Oh-My-Git-style playable command cards, the fourth reinvention of card-as-command after Oh My Git (2020), Gamify-IT (2022) and the print-and-play Git Gud (2024), and none of them pairs cards with real opponents ([GitHub](https://github.com/MikaStiebitz/Git-Mastery); [GitHub PR](https://github.com/MikaStiebitz/Git-Mastery/pull/101); [GitHub](https://github.com/pixari/gitvana)). The 2024 Learn Git Branching thread names the gap directly: commenters said it "doesn't show merge conflicts, actual file contents, or the messiness of real repositories", and one creator lamented that people say "oh this is cool!" and never return ([HN](https://news.ycombinator.com/item?id=41546769)). No tool found teaches force-push recovery between real people, a push rejected because a live collaborator pushed first, or blame on a teammate's commit; every tool scripts the other person (Learn Git Branching's "Faking Teamwork", Oh My Git's `remotes/friend`), Oh My Git's `pushed-something-broken` is the only force-push level anywhere, and the only multi-person exercises are a Polish three-role classroom game and a paid Boot.dev course ([Oh My Git levels](https://github.com/git-learning-game/oh-my-git/tree/main/levels); [git-collab-game](https://github.com/SrodixPL/git-collab-game); [Boot.dev](https://www.boot.dev/courses/learn-git-2)). "Multiplayer Git" has so far meant quizzing coworkers about their own repo history (jsomers/git-game, 459 stars; Git Game Show, 50 HN points in 2025), never playing Git against each other ([GitHub](https://github.com/jsomers/git-game); [HN](https://news.ycombinator.com/item?id=43638361)). Every content page should therefore lean on "the other player is real", because it is the one claim no competitor can make.

That positioning comes with a discoverability problem. There is no established search phrase for an asynchronous multiplayer Git game, and the head term "git game" is contested by the 2014 terminal game git-game/git-game (3,194 stars) and by Initial Commit's Devlands blog; autocomplete offers "git game to learn", "git game online" and "git game download" ([GitHub](https://github.com/git-game/git-game); [Google suggest](https://suggestqueries.google.com/complete/search?client=firefox&q=git%20game)). The practical response is to target Git-topic keywords (messages, flags, policies, releases) rather than the head term, add one FAQ line that distinguishes the site from the terminal git-game, and aim for the lists educators actually link: awesome-git (2,948 stars), MIT's Missing Semester resources, GitLab's "Git resources for visual learners" and GitHub Discussions answers, several of which still point at dormant tools (Git-It last pushed April 2024, gitstery May 2021, Visualizing Git February 2024) whose slots an active site can take ([awesome-git](https://github.com/dictcp/awesome-git); [MIT Missing Semester](https://missing.csail.mit.edu/2020/version-control/)).

## A pasted room link must preview as a result, not a homepage

The growth thesis is a link pasted into a team's Slack, and today that link unfurls as the generic landing page. Wordle shows what the fix looks like: it had 90 players on 1 November 2021, more than 300,000 on 2 January 2022 and over 2 million weekly by 9 January, after a player-invented emoji grid was built in as a Share button in late December; **1.2 million results were tweeted between 1 and 13 January** ([Wikipedia](https://en.wikipedia.org/wiki/Wordle)). The grid worked because it is spoiler-free, legible as plain text in any chat, and identical for everyone that day so it invites comparison; Wardle deliberately left the URL out and described the cryptic grids as "a club that you're either part of or not part of" ([Game Developer](https://www.gamedeveloper.com/marketing/josh-wardle-reflects-on-the-the-unconventional-road-to-wordle-s-success)). Git Game's growth loop depends on the link, so its version should include the room URL under the grid. Lichess shows the complementary pattern at scale: anonymous play, a public page per game, and a "share as GIF" export added in February 2020 in response to forum requests, across more than five million games a day ([lichess.org/about](https://lichess.org/about); [lichess on X](https://x.com/lichess/status/1233165658562682887)). The quantitative claims about link-preview images are weaker than they look: the widely cited "images get 150% more retweets" is a 2013 Buffer analysis, and the "2.3x CTR for optimised Open Graph images" figure could not be traced to a primary source, so treat the per-result image as a mechanism (Slack, Teams and Discord unfurl OG tags) rather than a promised lift ([Buffer](https://buffer.com/resources/the-power-of-twitters-new-expanded-images-and-how-to-make-the-most-of-it/)).

The backend already has the hard part (an event log, replays, scoreboards), so the missing pieces are cheap: a stable public URL per finished game and per replay, a server-rendered `og:image` showing the final commit graph and scoreboard, an optional GIF or short MP4 of the day-by-day replay, and a text block with one glyph per player per day that pastes cleanly. The static front end is no obstacle because Phoenix can render the image on request or precompute a PNG when the game ends while the page shell stays static. Identity without sign-up is proven (lichess is anonymous by default; Wordle kept stats in local storage) but local storage is fragile: when Wordle moved to nytimes.com some players' streaks reset and NYT had to tell them to revisit the old URL ([Tom's Guide](https://www.tomsguide.com/news/wordle-disaster-some-players-lose-their-streaks-in-transfer-to-nyt)). A per-browser anonymous id plus an optional export or "claim this history" link avoids both sign-up and loss.

A daily seeded room is the second-order version of the same idea and the one feature that would give the game what Wordle had and it lacks: the same puzzle for everyone. Every room today is different; a fixed daily seed, a single bot and 60-second days would create the comparable artifact a share grid needs. No Git daily puzzle exists; the developer dailies that do (Regexle's regex crossword, TerseQL's SQL golf) copy Wordle's six tries and share card but report no player numbers ([regexle.com](https://regexle.com/); [GitHub topic](https://github.com/topics/daily-puzzle)). The ceiling for a keyboard-centric developer site is suggested by Monkeytype, at roughly 15 million monthly visits, about 72% direct and 22% search, meaning habit and search rather than social spread ([Similarweb](https://www.similarweb.com/website/monkeytype.com/)). The decay is as well documented as the spike: Wordle stabilised at about half its March 2022 peak within a year, Semantle fell from 250,000 unique IPs a day, and 46 of 60 tracked daily games launched in 2022 against 12 in 2023 ([Wikipedia](https://en.wikipedia.org/wiki/Wordle); [Hey Good Game](https://www.hey.gg/blog/semantle)). A daily is a reach mechanic with a half-life, not an audience. It is also not a scheduled event: anyone plays at any time that day, which is what distinguishes it from the game nights that formed zero tables.

The planned Hacker News and r/git launch is a pulse, and the research is specific about its shape. Show HN rules favour exactly this project (something people can try, made by the poster, minimal sign-up), but the median Show HN scores 2 points, 50+ points is the top 6%, and the best window, Monday 00:00 UTC (Sunday evening US), lifts the odds of 50+ to only 10.8% against 2.6% at the worst slot ([Show HN guidelines](https://news.ycombinator.com/showhn.html); [Show HN by the Numbers](https://danfking.github.io/blog/2026/04/23/show-hn-by-the-numbers/)). A front page is worth roughly 1.4 GitHub stars per upvote with **92% of the effect spent inside 48 hours**; one post-mortem recorded 468 users on day one, 100 to 150 a day for three days and a few dozen a day by week two, and credited founder story, code examples and "framing as lessons rather than launches" ([Show HN by the Numbers](https://danfking.github.io/blog/2026/04/23/show-hn-by-the-numbers/); [Indie Hackers](https://www.indiehackers.com/post/front-page-of-hn-the-full-postmortem-traffic-lessons-surprises-cbe9e0a7f6)). The way to make a pulse leave something behind is to have the per-result share page and the room-link flow live before posting, and to pair the Show HN with an ordinary technical submission, since Show HN excludes blog posts: Plausible's single deep post drew 48,000 visitors in a week against 27,300 in the preceding fifteen months, Elixir event-sourcing has an HN audience of its own, and one business attributes about 10% of converting leads to years-old HN content ([Plausible](https://plausible.io/blog/blog-post-changed-my-startup); [HN](https://news.ycombinator.com/item?id=13338848); [HN](https://news.ycombinator.com/item?id=44958020)). Reddit is precise but unforgiving: one free open-source tool earned 100,000 impressions and about 108 visitors because moderators removed every post within 20 to 60 minutes, while r/WebGames (144,000 members) allows self-promotion if the title starts with the game's name ([dev.to](https://dev.to/damon-thomas/how-i-missed-out-on-thousands-of-views-launching-my-side-project-3d8d); [GummySearch](https://gummysearch.com/r/WebGames/)). Newsletters carry the second wave without a link penalty: Console.dev reaches 30,000 developers and reports that 68% have signed up for a featured tool, TLDR Dev reaches 470,000 at a 43% open rate, and Bluesky does not down-rank links ([console.dev](https://console.dev/advertise); [TLDR](https://advertise.tldr.tech/audiences/); [daily.dev](https://daily.dev/blog/where-developer-twitter-went-x-bluesky-mastodon-2026/)).

Two often-recommended mechanics have no evidence behind them. README badges and awesome-list entries show no measured traffic anywhere; the one article titled "badges that increased my GitHub visitor stats" contains no numbers and ends with a disclaimer ([dev.to](https://dev.to/dennislwm/readme-badges-that-increased-my-github-visitor-stats-25a5)). The single badge worth building faces outward: a shields.io dynamic badge a team can paste into its own README ("Played Git Game: 12 games") with the room link behind it, which turns a badge into the Slack-link loop rather than decoration ([shields.io](https://shields.io/)). Listing under GitHub topics and in awesome-git costs nothing but should carry zero expectations, measured through the repository's 14-day referrer insights. A public stats page is similar: Plausible publishes its own dashboard and the "open startup" pattern is established, but no source shows a stats page driving traffic on its own ([Plausible docs](https://plausible.io/docs/visibility)). Its value is honesty and newsletter material, and since success is measured in games completed, a read-only public counter of games completed, conflicts resolved and force-pushes survived is the one page that reports the right number.

## Educators just lost GitHub Classroom; teams search for force-push and rebase policy

GitHub Classroom was retired on 28 August 2026 after about ten years, 3.73 million students and educators and more than 305,000 classroom instances, with GitHub pointing instructors to Codio and the open-source Classroom 50 ([GitHub Community](https://github.com/orgs/community/discussions/205975)). Instructors are re-tooling for the 2026-27 year now, and the list of what their students get wrong has not changed in a decade. Isomöttönen and Cochez (2014) trace most problems to "the lack of a proper mental model", students treating version control as file storage and finding conflicts hard ([Springer](https://link.springer.com/chapter/10.1007/978-3-319-13206-8_9)); the Software Carpentry instructor notes say "the most common mistake is that learners push before pulling", that learners enter detached HEAD by running `git checkout [commit]` without a filename, and that they forget to `git add` after resolving a conflict ([Carpentries](https://swcarpentry.github.io/git-novice/instructor/instructor-notes.html)); the 544-point HN thread on "How to teach Git" turns on the invisible layers (working directory, staging, local, remote) and the fear that operations are destructive ([HN](https://news.ycombinator.com/item?id=18919599)); the 2025 JISE paper finds students "overwhelmed by the plethora of Git's detailed commands" and distracted by SSH and config setup ([JISE](https://jise.org/Volume36/n1/JISE2025v36n1pp1-12.pdf)). Pull-before-push, conflicts, detached HEAD recovery through reflog, and fear of loss are the game's mechanics, so a lesson page can be organised as a misconception map rather than a tutorial, and it removes the setup friction JISE names because nothing is installed.

The evidence that games teach Git is positive but thin, and the page should say so. One controlled classroom study, the Git Education Game (December 2024), compared two classes of the same course and found higher post-test pass rates and motivation in the game-taught class; it is a single institution published in a general electronics journal ([MDPI](https://doi.org/10.3390/electronics13244956)). Learn Git Branching and Oh My Git are endorsed in syllabi on the strength of visualisation, not learning-outcome studies, and neither models the social side of Git ([MIT Missing Semester](https://missing.csail.mit.edu/2020/version-control/); [ohmygit.org](https://ohmygit.org/)). A broader survey of 7,530 students found that using GitHub in class correlated with preparedness and belonging ([ACM](https://dl.acm.org/doi/10.1145/3287324.3287460)). To be linkable from the resource lists educators maintain (Missing Semester, Princeton Research Computing, The Odin Project), the page should follow the conventions those communities use: the Carpentries' Questions, Objectives and Key Points blocks with per-episode timing, a 45-minute block of 15 minutes of concept and 30 minutes of hands-on play as in Beckman et al., a CC-BY licence on the lesson text and a Zenodo DOI, which both git-novice and the Git Teaching Kit carry ([Carpentries template](https://github.com/carpentries/lesson-example); [JSE 2020](https://www.tandfonline.com/doi/full/10.1080/10691898.2020.1848485); [Git Teaching Kit](https://git-teaching-kit.netlify.app/); [Zenodo](https://zenodo.org/records/3264950)).

The tabletop version has an empty niche to fill. Instructors already improvise physical props for the collaboration and conflict episodes (two instructors role-playing with different-coloured hats or sticky notes, whiteboard graphs, sticky-note command quizzes), yet no unplugged version-control activity exists in CS Unplugged or the Carpentries canon ([Carpentries](https://swcarpentry.github.io/git-novice/instructor/instructor-notes.html); [NIST guide](https://pages.nist.gov/git-novice-MSE/guide/)). Print-and-play communities have a precise checklist for a download page: PDF only, a 9-up poker layout (2.5 x 3.5 inches), **3 mm bleed with cut marks**, sRGB, 300 gsm matte stock, printer set to Actual Size, a README under 100 words covering how to print, how to assemble and what is in the box, a CC BY or BY-SA licence if remixing is allowed, and listings on BoardGameGeek's Print & Play forum, itch.io and r/printandplay ([chitmunk.com](https://chitmunk.com/learn/print-and-play-guide); [BGG](https://boardgamegeek.com/thread/3327182/how-much-bleed-do-you-think-is-needed-for-cards-an)). Directories such as Tabletop Bellhop's 300+ free PnP titles and the American Library Association's Print & Play page are standing link sources ([Tabletop Bellhop](https://tabletopbellhop.com/gaming-advice/free-pnp-board-games/); [ALA](https://games.ala.org/print-play-games/)). The crowdfunding precedents are instructive but all skew to children: Robot Turtles raised $631,230 from 13,765 backers and Potato Pirates S$258,408 from 5,061, and both grew through schools and educators afterwards; no adult-oriented Git tabletop game has a Kickstarter precedent ([Kickstarter](https://www.kickstarter.com/projects/danshapiro/robot-turtles-the-board-game-for-little-programmer); [Kickstarter](https://www.kickstarter.com/projects/codomo/potato-pirates-the-tastiest-coding-card-game/description)). The classroom guide and the PnP page are therefore the deck's distribution, not a prelude to a campaign.

Engineering teams search for policy, and the policy has consolidated around the game's failure modes. Atlassian now calls Gitflow "a legacy Git workflow" that "has fallen in popularity in favor of trunk-based workflows", DORA's research finds elite performers 2.3 times more likely to practise trunk-based development, and 2026 checklists such as Gitmore's 19-item "Git Workflow Standards" repeat "never force push to main or protected branches", short-lived branches under two days and PRs under 200 lines ([Atlassian](https://www.atlassian.com/git/tutorials/comparing-workflows/gitflow-workflow); [DORA](https://dora.dev/capabilities/trunk-based-development/); [Gitmore](https://gitmore.io/resources/checklists/git-workflow-standards-checklist)). Branch-protection deep dives published in 2026 explain that disabling force push "completely forbids rewriting history on the branch" ([mcginniscommawill.com](https://mcginniscommawill.com/posts/2026-03-24-github-branch-protection-deep-dive/)). Demand matches: "git rebase vs merge" is the first autocomplete for "git rebase", "How do I properly force a Git push?" has 3.0 million views and "When do you use Git rebase instead of Git merge?" 1.2 million ([SO 804115](https://stackoverflow.com/questions/804115/when-do-you-use-git-rebase-instead-of-git-merge)). Five page types follow, each able to end with "practice the failure mode in the game": a branching-strategy comparison (trunk-based, GitHub Flow, Gitflow), a team conventions checklist, a force-push and protected-branch explainer tied to the `push --force` and reflog cards, a rebase-versus-merge policy page tied to `rebase -X ours/theirs`, and a blame-culture page tied to the blame card and Google's blameless postmortem chapter ([Google SRE](https://sre.google/sre-book/postmortem-culture/)).

Teams also run Git sessions at predictable lengths with no game in them. Formats range from Beckman's 45-minute block through GitKraken's 4-hour "Git Fundamentals Masterclass" for up to 20 people and half-day Carpentries segments to two-day advanced workshops, and Hacktoberfest's 300+ community events each autumn run beginner Git sessions; none uses a game-based opener ([GitKraken](https://training.gitkraken.com/); [Hacktoberfest](https://hacktoberfest.com/events/)). Remote team-building is priced at $30 to $105 per person in 2026 (most events $40 to $65), while the games engineering teams actually use day to day are free, no-install, 15-minute browser party games such as Codenames Online, Gartic Phone and Skribbl, and the developer-specific lists (Superglue, Shake) contain no Git or version-control game at all ([eventsinminutes](https://www.eventsinminutes.com/blog/virtual-team-building-cost-per-person-2026/); [growrk](https://growrk.com/blog/games-for-remote-teams); [superglue.games](https://superglue.games/team-building-activities-for-developers/)). A runbook page with 15-, 30- and 60-minute scripts built on 60-second and 5-minute days competes in that empty long tail, and it describes how a facilitator runs a game inside a meeting they already have, which is the opposite of a scheduled game night.

## What not to build

A global leaderboard is the clearest no. Advent of Code retired its global leaderboard for 2025 after ten years because it had become "one of the largest sources of stress" for its creator, infrastructure and users, drew DDoS attacks and LLM solvers, and led many to conclude "that they were somehow worse programmers because their own times didn't compare"; only private leaderboards with organiser-set rules survive ([Advent of Code](https://adventofcode.com/2025/about)). A controlled study of 4,500 new players found the no-leaderboard condition outperformed a personalised leaderboard and in some cases a Top 5 board ([arXiv](https://arxiv.org/abs/1707.03704)). The game's per-room scoreboard and an optional private team leaderboard with owner-set rules (60-second days only, for example) are the evidence-backed shape.

Calendar-day streaks fail the one test their best practitioner sets. Duolingo's retention lead says streaks only work "layered atop apps users genuinely want daily" and otherwise "you're only going to waste a lot of time", and half of its 600-plus streak experiments lost ([Lenny's Podcast transcript](https://github.com/ChatPRD/lennys-podcast-transcripts/blob/main/episodes/jackson-shuttleworth/transcript.md)). GitHub removed contribution streaks in 2016 to focus "on the work you're doing rather than the duration of your activity" ([freeCodeCamp](https://www.freecodecamp.org/news/dont-break-the-chain-why-github-s-streaks-will-be-sorely-missed-by-many-4fff90bc2a38/)). A 24-hour asynchronous day makes a calendar streak punishing by design, and local-storage streaks break on migration. A plain "games completed" count is enough.

Badges, XP and achievements have no data behind them here. README badges show no measured traffic anywhere, PR-count incentives bred spam at Hacktoberfest until two spam-labelled PRs became a ban, and the entire 2024 to 2026 cohort of Git games ships XP and shops without a single published player number ([dev.to](https://dev.to/dennislwm/readme-badges-that-increased-my-github-visitor-stats-25a5); [freeCodeCamp](https://www.freecodecamp.org/news/how-anyone-can-participate-in-hacktoberfest/)). The one nuance worth recording is a 51,104-player log study in which achievement features predicted retention for early players while social features predicted it for veterans, which, if anything, says to measure completion drop-off before designing rewards ([arXiv](https://arxiv.org/abs/1702.08005)).

Scheduled game nights formed zero tables in the sibling project, and the external evidence agrees: a 2025 study of a team multiplayer game found players "perform worse when teaming with friends and subsequently engage in less gameplay" unless their schedules aligned, and asynchronous play is the design that removes that coordination cost ([ICIS 2025](https://aisel.aisnet.org/icis2025/hti/hti/33/)). Invest in artifacts that work whenever a link is opened.

Generic "learn Git" and cheat-sheet pages chase shrinking, saturated demand: Wikipedia's Git views fell from 54,876 a month in 2024 to 35,914 in 2026 and the official, Atlassian, GitLab and GitHub Education sheets already own the "git cheat sheet" results ([Wikimedia](https://wikimedia.org/api/rest_v1/metrics/pageviews/per-article/en.wikipedia/all-access/user/Git/monthly/20240101/20261001); [git-scm.com](https://git-scm.com/cheat-sheet)). Quiz and glossary pages inherit gastrointestinal search pollution and have never reached 150 HN points. A Product Hunt launch delivers transient, less engaged traffic to a maker audience: one #4 Product of the Day saw pages per session fall from 5.17 to 2.98 ([The Hack Stack](https://thehackstack.substack.com/p/a-successful-product-hunt-launch)). A worktree page would ride a real 2026 trend but has no card to land on; defer it unless the deck gains one. And do not crowdfund the deck yet: every programming-themed tabletop success is a children's game, and the educator channel the PnP page opens is the multiplier those games used.

## Conclusion

The research reframes Git Game's content problem. The site does not need to teach Git; it needs to explain what Git just said and what just happened to the player, because those are the two intents the market still searches for and the two formats that get re-shared for a decade, and the game is the only property on the web that produces both artifacts, real output and a real other person, every sixty seconds. Decoder and recovery pages are therefore not marketing attached to a game; they are the game's own events turned into stable URLs, and the version footer that Git-accuracy demands is also what makes them structurally different from every ranking page.

The second shift is in what "growth" means for a project measured in games completed. Every channel in the evidence is a pulse that decays in days, so the site's job is to leave something behind after each one: a replay that previews as a result in Slack, a classroom page an instructor can cite, a PnP file a library lists, a daily seed people return to on their own clock. Build the share artifact before the launch, let the Git release calendar set the editorial rhythm, and treat the Git 3.0 transition in spring 2027 as both the biggest news hook of the year and a forcing function to re-verify every quoted line of output.
