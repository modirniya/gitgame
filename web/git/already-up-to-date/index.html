Already up to date. and Everything up-to-date

Both mean Git found nothing to do. They are spelled differently because they come from different parts of Git, and they check different things. 

%CAPTURE:pull-already-up-to-date%
%CAPTURE:push-everything-up-to-date%

What each one checked

git pull fetches, then asks whether origin/main has a commit your main lacks. If it doesn't, there is nothing to merge or rebase, and the merge machinery says Already up to date.: a sentence, with a full stop.

git push asks the opposite: whether the remote's main lacks a commit yours has. If it doesn't, there is nothing to send, and the push machinery says Everything up-to-date: hyphens, no full stop. Git dropped the hyphens from the merge's message years ago and never from the push's. Both are correct output today, so these pages leave them as they are.

The line between them

git status doesn't talk to the remote. It compares your main with origin/main as of your last fetch, and counts: ahead by the commits you have and it doesn't, behind by the reverse. 

%CAPTURE:status-ahead%

Ahead means a push has something to send. Behind means a pull has something to bring. Both at once means the branches have diverged, which is where the forced update page leaves bot. Neither, and the two commands above print their nothing-to-do lines:
