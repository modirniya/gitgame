Someone force-pushed over my commit

Someone pushed with --force, and main no longer has your commit. Your clone still does, which is all you need. Here is how it looks, how to put it back, and the one command that would quietly lose it. 

%CAPTURE:fetch-after-force%

Put it back on top

git status says the branches have diverged, one commit each: theirs on origin/main, yours on your main, and git log shows yours at the top. Rebase your branch onto what origin/main is now: Git takes your commit off, moves main to their tip, and replays yours on top. The push after it is a fast-forward. 

%CAPTURE:recover-after-force%

Both commits are on main again, yours with a new hash, since it has a new parent. If the two touched the same lines, the replay stops on a conflict first. What the forced push itself did is on the forced update page.

The pull that would drop it

git pull --rebase looks like the same move, and here it isn't. A pull works out which commits are yours from the history of origin/main as your clone has seen it, the fork point. A commit that was once on origin/main counts as upstream's, and since it is no longer there, the rebase drops it, and says nothing: 

%CAPTURE:pull-rebase-drops%

Successfully rebased, and the commit is gone from the log. ORIG_HEAD still points to where the branch was before the rebase, so git reset --hard ORIG_HEAD is the way back, and then the rebase above, with origin/main named on the command line, which turns the fork-point rule off.

If it isn't on your machine

Then it is on the forcer's. Their remote-tracking branch keeps a reflog of its own, and origin/main@{1} is where main was before their push. Pushing that back is one command, with a lease so it can't erase anything newer: 

%CAPTURE:undo-force-push%

That restores main to before the force, your commit included; the forcer's own commit is now the one off main, and a rebase and a push, as above, puts it back properly. Hosts keep an erased commit for a while too, and show forced pushes in a branch's activity, so its hash can still be found there.

Why the game does this to you

In %BRAND% a push --force erases every commit after the forcer's pointer, and the erased commits go back to their owners' local branches: the same place Git leaves them. Next day a pull puts you back at the tip and your push lands on top, which is the rebase above. A reflog armed in your pack does it at once: it fires inside the forcer's pack and puts your erased commits back on top of main before the day is over.
