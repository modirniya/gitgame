What Git said

Every command in a day of %BRAND% prints what Git prints: ! [rejected], (forced update), Already up to date. These pages take the lines one at a time: what Git checked, what to do now, and why a day of the game did it to you. Every line on them is captured from a real Git by a script, never typed, and each page names the Git that printed it.

When you pushed

  • ! [rejected] main -> main (non-fast-forward) Rejected: non-fast-forward

    Someone's commit reached main before yours. Why Git refuses, the two hints it prints, and the pull that fixes it.

  • + 7a20dd4...864afd7 main -> main (forced update) Forced update

    The push went through, and that is the problem. What --force erased, what the others see, and what --force-with-lease refuses.

When you pulled

  • CONFLICT (content): Merge conflict in api.py Merge conflict

    Two commits changed the same lines. The markers Git leaves, resolving by hand under a merge and a rebase, and what -X ours and -X theirs keep.

  • Fast-forward Successfully rebased and updated refs/heads/main. Merge made by the 'ort' strategy. Fast-forward and rebased

    The three ways a pull lands, and which one you get.

  • Already up to date. Everything up-to-date Nothing to do, two spellings

    Why a pull and a push spell it differently, what each checked, and the git status line between them.
