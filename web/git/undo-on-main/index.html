what Git said teach play

Undo a commit that's on main

The commit is pushed, so other clones may have it already. The undo has to be something they can pull: a new commit that takes the change back.

Revert: a commit that undoes a commit

%CAPTURE:revert%

git revert HEAD makes a new commit with the inverse change, named after the one it undoes, and leaves the history as it was. The push is a fast-forward, and everyone's next pull brings the fix. To revert a merge commit, add -m 1: which of its parents counts as the line you are staying on.

Why not a reset

%CAPTURE:reset-and-push%

git reset --hard HEAD~1 takes the commit off your main, but the remote's main still has it, and a push that would move main backwards is rejected. --force makes the remote take it, and now the commit is erased from main for everyone, with every other clone diverged: the forced update page's situation. On a branch nobody else has pulled, that is fine. On main, revert.

Not pushed yet

If the commit never left your clone there is nobody to tell. git reset --soft HEAD~1 takes it back and keeps its changes staged (on the lost commit page), and git commit --amend rewrites it in place.

Why the game does this to you

In %BRAND% the revert card does what Git's does: put on a face-up bug on main, it no longer counts as a bug at the release, and the commit stays where it is. The only card that takes a commit off main is push --force, with its sin token, which is Git's lesson in a card.
